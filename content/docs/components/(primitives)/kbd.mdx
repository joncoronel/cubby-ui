import { Kbd } from "@/registry/default/kbd/kbd";

Kbd renders a keyboard key as a soft keycap: a translucent fill with a one-pixel lip, both taken from the color of the text around it, so it reads on the page, in a tooltip and on a primary button without a variant per surface. Pass `keys` to draw a whole shortcut on one cap, and named keys like `mod` and `shift` become the right legend for the user's platform: <Kbd keys={["mod", "k"]} platform="mac" /> on a Mac, `Ctrl+K` everywhere else.

### Named Keys

Named keys are case-insensitive and turn into the platform's legend. Symbols carry a hidden label, so a screen reader says "Command" rather than the glyph's name. Any other single character is uppercased; longer names are drawn as written.

<ComponentPreview component="kbd" example="kbd-special-keys-with-auto-conversion" />

| Key                    | Mac | Windows and Linux |
| ---------------------- | --- | ----------------- |
| `mod` (`cmd`)          | ⌘   | Ctrl              |
| `meta`                 | ⌘   | Win               |
| `ctrl`                 | ⌃   | Ctrl              |
| `alt` (`option`)       | ⌥   | Alt               |
| `shift`                | ⇧   | Shift             |
| `enter` (`return`)     | ↵   | Enter             |
| `backspace`            | ⌫   | Backspace         |
| `delete`               | ⌫   | Del               |
| `tab`                  | ⇥   | Tab               |
| `capslock`             | ⇪   | Caps Lock         |
| `esc`, `space`         | Esc, Space | Esc, Space |
| `up`, `down`, `left`, `right` | ↑ ↓ ← → | ↑ ↓ ← → |

### Platform

`platform` defaults to `"auto"`, which reads the user's OS. Set `"mac"` or `"windows"` to pin one. A key rendered on the server shows Mac legends until it hydrates; keys in menus, dialogs and tooltips mount on the client and are right from their first frame.

<ComponentPreview component="kbd" example="kbd-platform-detection" />

### Group

Wrap several `Kbd` in `KbdGroup` to show a shortcut as separate caps, or a sequence with words between them. The group is an outer `kbd`, the HTML way to mark up a combination, and its loose text stays quiet.

<ComponentPreview component="kbd" example="kbd-group" />

### Variants

`default` is the filled keycap. `outline` takes the outline Button's fill and edge, for a key that sits on a muted plate; it keeps that surface's colors, so use `default` on a solid fill. `ghost` is the legend alone, for menus and dense rows.

## API Reference

Kbd and KbdGroup render `kbd` elements. Other props pass through to the element.

### Props

#### Kbd

One key, or a whole shortcut drawn on a single cap.

<ApiPropsList>

<ApiProp name="keys" fullType="string[]" simpleType="array">
  Keys of one shortcut. Named keys become the platform's legend; other single characters are uppercased. When set, `children` is ignored.
</ApiProp>

<ApiProp name="separator" fullType="React.ReactNode" simpleType="ReactNode">
  Placed between `keys`. Defaults to nothing on Mac and `+` elsewhere.
</ApiProp>

<ApiProp name="platform" fullType='"mac" | "windows" | "auto"' simpleType="string" defaultValue='"auto"'>
  Legend set for named keys. `"auto"` reads the user's OS; `"windows"` also covers Linux.
</ApiProp>

<ApiProp name="variant" fullType='"default" | "outline" | "ghost"' simpleType="string" defaultValue='"default"'>
  Filled keycap, outlined key, or the legend alone.
</ApiProp>

<ApiProp name="size" fullType='"sm" | "md" | "lg"' simpleType="string" defaultValue='"md"'>
  Height and text size of the key.
</ApiProp>

<ApiProp name="pressed" fullType="boolean" defaultValue="false">
  Draws the key held down. Sets `data-pressed` for your own styles.
</ApiProp>

</ApiPropsList>

#### KbdGroup

An outer `kbd` that lays out several keys as one shortcut. Takes standard `kbd` props.
