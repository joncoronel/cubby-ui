A switch toggles a single setting on or off and applies the change immediately. Use it for instant preferences like notifications or dark mode, not for choices a user submits later with a form (reach for [`Checkbox`](/docs/components/checkbox) there).

### Shapes

Use `shape` to set the thumb's silhouette. It controls the aspect ratio, the corner radius, and the travel distance together, and the track follows the thumb so the two always match.

<ComponentPreview component="switch" example="switch-shapes" />

| Shape      | Description                                          |
| ---------- | ---------------------------------------------------- |
| `circle`   | The default, a round thumb.                          |
| `pill`     | A wider, rectangular thumb.                          |
| `squircle` | A squared-off thumb, for a more mechanical look.     |

`squircle` uses the CSS `corner-shape` property, which draws a superellipse rather than a quarter-circle at each corner. Browsers without it fall back to a plain rounded square: the fallback deliberately uses a smaller radius, because the near-50% radius a squircle needs would render as a plain circle without `corner-shape` to reshape it.

Every shape sets its radius as a fraction of `--thumb-size` rather than a fixed pixel value, so the corners stay proportional across sizes instead of reading too round at `xs` and too sharp at `default`.

### Sizes

Use `size` to set the thumb height. Shape and size are independent, so every shape works at every size.

<ComponentPreview component="switch" example="switch-sizes" />

| Size      | Thumb | Track height | Where it fits                                        |
| --------- | ----- | ------------ | ---------------------------------------------------- |
| `xs`      | 14px  | 18px         | Dense rows: menu items, toolbars.                    |
| `sm`      | 16px  | 20px         | Compact settings rows and cards.                     |
| `default` | 20px  | 24px         | Standalone form control.                             |

The menu components use `size="xs"` for their `variant="switch"` items, so a switch inside a [Dropdown Menu](/docs/components/dropdown-menu), [Context Menu](/docs/components/context-menu), or [Menubar](/docs/components/menubar) already matches the surrounding text.

For a size the scale does not cover, set `--thumb-size` directly. It also accepts responsive variants, which the preset cannot:

```tsx
<Switch className="sm:[--thumb-size:--spacing(3.5)]" size="sm" />
```

## API Reference

The Switch component is built on top of [Base UI's Switch](https://base-ui.com/react/components/switch). All Base UI props are supported. The documentation below only covers custom props specific to our implementation.

For the complete Base UI API, see the [Base UI Switch documentation](https://base-ui.com/react/components/switch).

### Props

#### Switch

Toggle control for binary on/off states. Wraps Base UI's `Switch.Root` and `Switch.Thumb`.

<ApiPropsList>

<ApiProp
  name="shape"
  fullType='"circle" | "pill" | "squircle"'
  simpleType="string"
  defaultValue='"circle"'
>
  Controls the aspect ratio, corner shape and animation travel distance of the switch thumb. Use `"pill"` for a wider, more rectangular thumb, or `"squircle"` for a squared-off one. The track picks up the same corner treatment, so both stay in step.
</ApiProp>

<ApiProp
  name="size"
  fullType='"xs" | "sm" | "default"'
  simpleType="string"
  defaultValue='"default"'
>
  Thumb height, which drives the track dimensions. `"xs"` (14px) suits dense rows like menu items, `"sm"` (16px) compact settings rows. Sets `--thumb-size`, so `className` can still override it for a one-off or responsive size.
</ApiProp>

</ApiPropsList>

Switch does not expose a `variant` prop like the other form fields. The unchecked track uses `--switch-track`, a translucent overlay that adapts to whatever substrate it sits on, so one track color works on a page, a Card, or a toolbar. It is a separate token from `--input-elevated` because a switch has no border: the fill *is* the control's boundary, so it carries more weight in dark mode than a field background would. The thumb is white in both themes, contrasting with the track and the parent surface alike. See the [Surfaces](/docs/getting-started/surfaces) docs.

Hover moves the track one step further along that overlay, which darkens it in light mode and lightens it in dark from a single rule. A checked track darkens in both, since lightening the primary reads as disabled. Set `--switch-track` and `--switch-track-hover` to retune both.

The thumb is absolutely positioned and placed entirely by a transform, so the 2px inset around it is a single offset rather than something the layout divides. That matters at fractional device pixel ratios, where centring a thumb inside a track can round to a different number of device pixels on the top edge than the bottom and read as an off-centre thumb. For the same reason the track's width, the thumb's width and the travel distance are all snapped to whole pixels with CSS `round()`; browsers without it fall back to the unrounded values. A `p-*` class will not change the inset.
