The filter bar shows active filters as chips that read as a sentence ("Status is In progress"), plus a "Filter" button whose menu takes you from a field to its value in one popup. Use it for list and table views where users refine results by several conditions at once, the pattern you see in Linear, Notion, and Stripe.

For a single dropdown of options tied to a form field, use [`Combobox`](/docs/components/combobox) instead.

## Composition

```text
Filters                 (FiltersProvider + FiltersBar)
└── FiltersBar
    ├── FilterChips
    │   └── FilterChip
    │       ├── FilterChipField
    │       ├── FilterChipOperator
    │       ├── FilterChipValue
    │       └── FilterChipRemove
    ├── FilterActiveCount
    ├── FilterActions
    │   └── FilterAddButton (plus a built-in clear segment)
    ├── FilterAddButton
    └── FilterClearButton
```

Drive the bar with a `fields` config and a `value` array of active filters. Each field's `type` picks the value control and its default operators. Without `children`, the bar renders `FilterChips` and `FilterActions`, a capsule holding the add button and, once filters exist, a clear segment; pass `children` to compose the parts in any order.

```tsx
const fields: FilterField[] = [
  {
    id: "status",
    label: "Status",
    type: "select",
    options: [
      { value: "todo", label: "Todo" },
      { value: "done", label: "Done" },
    ],
  },
  { id: "title", label: "Title", type: "text" },
];

const [value, setValue] = React.useState<FilterValue[]>([]);

return <Filters fields={fields} value={value} onValueChange={setValue} />;
```

## Features

- Per-type operators with sensible defaults (`is`, `contains`, `between`, `is empty`), overridable or hideable per field.
- Operators declare a value `shape` (`"none"` / `"scalar"` / `"range"`), so custom operators get the right control automatically; `is empty` drops the value segment, and any `"range"` operator gets paired min/max inputs.
- A two-step add menu: pick a field and the same popup slides to its values (or an input for text and number fields), so a chip only appears once it has a value. `Backspace` in the empty search, or the field token, goes back.
- Searching the add menu also finds values across fields ("Done" in Status), so the common case takes one step. A value found for a field that already has a filter joins that filter.
- Chips open their own space as they arrive and close it as they leave, so neighbors slide instead of jumping; operator and value labels morph in place with [`TextMorph`](/docs/components/text-morph).
- Multiselect chips stack the picked options' icons beside a count, and multiselect values toggle live in the add menu while the chip grows behind it.
- Colored dots or icons on options keep a dense bar scannable; fields accept an optional `icon` too.
- `prefix` / `suffix` on text and number fields for currency, units, or symbols; `maxSelections` caps a multiselect.
- Number fields are spinner-free (Base UI) with arrow-key stepping and wheel scrubbing (scroll to adjust while focused).
- An optional `shortcut` key opens the add-filter menu, with a `Kbd` hint on the button.
- Once a filter exists, the Filter button folds down to its "+" icon, since the chips beside it already say what it adds; it keeps its name for screen readers.
- Controlled and uncontrolled: pass `value` + `onValueChange`, or `defaultValue`. Because it is controlled, syncing to the URL (nuqs) is trivial.
- The `custom` field type renders any control through `renderValue`, for dates, sliders, or bespoke inputs.
- Searchable, keyboard-navigable field and value pickers, inherited from `Combobox`.
- A chip still waiting on its value (an empty text input, say) shows a dashed edge, since it narrows nothing yet.

### Field types

Use `type` to pick the value control. `select` and `multiselect` open a searchable list, `text` and `number` render inline inputs that grow with what you type, and `custom` renders your own control through `renderValue`. A `custom` field skips the value step: the chip is added straight away and focus moves into your control.

| Type            | Value control                              | Value shape                     |
| --------------- | ------------------------------------------ | ------------------------------- |
| `"select"`      | Searchable single-select list.             | `string \| null`                |
| `"multiselect"` | Searchable multi-select list.              | `string[]`                      |
| `"text"`        | Inline text input.                         | `string`                        |
| `"number"`      | Inline number input, paired for `between`. | `number \| null \| NumberRange` |
| `"custom"`      | Your control via `renderValue`.            | `unknown`                       |

### Overflow

When the chips outgrow the row, they scroll sideways behind edge fades, while the Filter and Clear buttons stay in view. Trackpads, touch, and a plain mouse wheel all scroll the strip, and a chip you add or change scrolls into view. The strip isn't a tab stop of its own, since every chip in it is, and the browser scrolls a focused chip into view. Set `overflow="wrap"` to flow chips onto new rows instead, for narrow panels where a taller bar is fine.

### Server-side filtering

`onValueChange` fires on every edit, including keystrokes and chips still waiting on a value. Send only complete filters, and let typing settle before you fetch:

```tsx
const [value, setValue] = React.useState<FilterValue[]>([]);
const query = React.useDeferredValue(
  value.filter((filter) => {
    const field = fields.find((f) => f.id === filter.field);
    return field !== undefined && isFilterComplete(field, filter);
  }),
);
// fetch with `query`
```

### State outside the bar

`Filters` is `FiltersProvider` + `FiltersBar` composed. Use them separately when UI outside the flex row (a results count, saved views, an apply button) should read or mutate the same state through `useFilters`.

```tsx
<FiltersProvider fields={fields} value={value} onValueChange={setValue}>
  <PageHeader>
    <FilterSummary /> {/* reads useFilters() */}
  </PageHeader>
  <FiltersBar />
  <ResultsCount />
</FiltersProvider>
```

## Accessibility

The add menu is a `Popover` holding inline `Combobox` lists, and the value lists on chips are `Combobox` popups, so type-to-search, arrow-key navigation, and selection follow the ARIA combobox pattern. The operator menu is a `DropdownMenu` radio group. Each chip is a group labeled with its full filter (for example, "Status is In progress"), and every segment is self-describing: the operator trigger is named "[field] operator: [operator]", value triggers and inputs are named "[field] value: ..." (including string affixes), and the remove control is "Remove [field] filter". Pressing `Backspace` or `Delete` on a chip's remove button removes the filter (on the operator or value it's left alone, since there it reads as editing that part), and focus moves to the neighboring chip (or the add button) instead of dropping to the page.

Adding, removing, and clearing filters are announced through a visually hidden status region in the bar ("Added Status is Done", "Removed Status is Done", "Cleared all filters"), so screen reader users hear the change even though focus lands elsewhere. A number the add menu can't read shows an "Enter a number" hint tied to the input. The shortcut key is exposed as `aria-keyshortcuts` rather than read as part of the button's name.

The Backspace removal and focus rescue rely on the `data-slot` attributes (`filter-chip`, `filter-chip-remove`, `filter-add`); custom chip children should preserve those slots to keep the keyboard behavior.

## API Reference

Filters is a custom component composed from Cubby UI primitives. It has no Base UI root of its own; the value and field pickers are [`Combobox`](/docs/components/combobox) and the operator menu is [`DropdownMenu`](/docs/components/dropdown-menu).

### Props

#### Filters

`FiltersProvider` + `FiltersBar` composed, for the common case. All props below except `shortcut` and `overflow` belong to the provider; those two and div props flow to the bar.

<ApiProp name="overflow" fullType='"scroll" | "wrap"' defaultValue='"scroll"'>

</ApiProp>

<ApiProp name="labels" fullType="Partial<FiltersLabels>">

  `selectValue`, `enterValue`, `value`, `min`, `max`, `and` (joins a range),
  `fields` and `values` (add menu group headings), `back`, `done`,
  `invalidNumber`, `filtersCleared`, `operator`, `operators` (translated operator names by id, e.g. `{ is_not: "n'est pas" }`), plus five functions:

</ApiProp>

#### FiltersProvider

Owns filter state and provides it via context without rendering layout. Takes the state props from `Filters` (`fields`, `value`, `defaultValue`, `onValueChange`, `size`, `allowDuplicateFields`, `labels`) plus `children`.

#### FiltersBar

The flex row. Renders the default layout (`FilterChips`, `FilterActions`) unless `children` is passed. Takes `shortcut`, `overflow`, and div props. With `children`, `shortcut` has nothing to attach to; pass it to your `FilterActions` or `FilterAddButton` instead.

#### FilterActions

The add and clear actions as one capsule, built like a chip. The add button sits inside as a segment and folds to "+" once filters exist (then showing an "Add filter" tooltip, with the shortcut key if set), while a clear segment (a filter-remove icon with a "Clear filters" tooltip, set apart by a hairline) opens in the same beat. Takes `shortcut` and div props. Pass `children` to compose the capsule yourself from `FilterActionsAdd` and `FilterActionsClear`, plus segments of your own (style them with the exported `FILTER_SEGMENT` and `FILTER_SEGMENT_INTERACTIVE` classes so they match):

```tsx
<FilterActions>
  <FilterActionsAdd shortcut="f" />
  <button className={cn(FILTER_SEGMENT, FILTER_SEGMENT_INTERACTIVE)}>
    Save view
  </button>
  <FilterActionsClear />
</FilterActions>
```

#### FilterActiveCount

The number of active filters as plain muted text ("3 active", from `labels.activeCount`), with the number morphing as it changes. It counts complete filters only (see `isFilterComplete`), and like `FilterClearButton` renders nothing at zero. Takes span props.

#### FilterClearButton

A standalone text button that clears every filter, for layouts that keep the actions apart. Renders nothing while no filters are active, so compositions don't need to wrap it in a conditional. `FilterActions` has its own clear segment, so use one or the other.

#### FilterChips

Renders a `FilterChip` for every active filter, in order. Use it in `children` mode to place the chip list among your own chrome. In a scrolling bar it wraps the chips in their own sideways-scrolling strip, so whatever you place beside it stays in view.

#### FilterChip

A single chip. Without `children` it renders the field, operator, value, and remove segments (`FilterChipField`, `FilterChipOperator`, `FilterChipValue`, `FilterChipRemove`); pass `children` to compose them yourself, alongside segments of your own. Inside a chip, `useFilterChip()` gives the current `filter`, `field`, and `size`.

<ApiPropsList>

<ApiProp name="filter" fullType="FilterValue">
  The active filter this chip represents.
</ApiProp>

<ApiProp name="field" fullType="FilterField">
  The field definition. Resolved from the `Filters` context by `filter.field`
  when omitted.
</ApiProp>

</ApiPropsList>

#### FilterAddButton

The add menu: a trigger and a popup that steps from the field list to the chosen field's value. Picking a value adds the filter and closes the menu; multiselect values toggle in place until you press Done or close it.

<ApiPropsList>

<ApiProp name="shortcut" fullType="string">
  Key that opens this menu from the keyboard (e.g. `"f"`). Adds a `Kbd` hint to
  the trigger.
</ApiProp>

</ApiPropsList>

### Hooks

`useFilters()` exposes the bar's state and actions (`filters`, `fieldsById`, `addFilter`, `updateFilter`, `removeFilter`, `clearAll`) to anything rendered inside a `FiltersProvider`. It re-renders on every filter edit; performance-sensitive leaves can subscribe to `useFiltersState()` (just `filters`) or `useFiltersActions()` (config and actions, stable while a value is being typed) instead. `useFilterChip()` exposes the current chip's `filter`, `field`, and `size` inside a `FilterChip`.

State merging uses [useControllableState](/docs/hooks/use-controllable-state), installed as a shared hook.

### Types

#### FilterField

A discriminated union keyed on `type`. Every variant has `id`, `label`, and optional `icon`, `operators`, and `disabledOperators`. `select` and `multiselect` add `options` (`multiselect` also takes `maxSelections`); `text` and `number` take `prefix` / `suffix`; `custom` adds `renderValue`, optional `defaultValue`, and optional `formatValue` (the value as text, for the chip's accessible name and for telling whether the filter is complete; strings, numbers, and booleans read as themselves without it). `renderValue` renders as its own component, so it can use hooks.

#### FilterValue

```ts
interface FilterValue {
  id: string;
  field: string;
  operator: string;
  value: unknown;
}
```

### Helpers

#### createFilter

Creates a `FilterValue` with a stable id, the field's first operator, and a typed empty value. Pass a partial to override any of them.

```ts
createFilter(statusField, { value: "in_progress" });
```

#### patchFilter

Applies a partial update to a filter, reseeding the value when an operator change alters the value shape (e.g. `eq` to `between`).

#### asFilterValues

Coerces unknown JSON (e.g. a parsed URL param) into a `FilterValue[]`, dropping entries with a malformed envelope. Pair it with the controlled API when restoring filters from untrusted sources; see the nuqs example.

#### formatFilterValue / describeFilter

`formatFilterValue` renders a filter's value as a human-readable string; `describeFilter` prepends the field and operator ("Status is In progress"). The chip's `aria-label` uses `describeFilter`, so custom UIs can stay consistent with it.

#### scalarOperatorFor / withOption

`scalarOperatorFor` returns the field's first operator that takes a single value, which is the one filters added from the menu start on. `withOption` folds a picked option into a value: a multiselect gains it (respecting `maxSelections`), any other field is replaced by it.

#### isFilterComplete

Whether a filter narrows anything yet: its operator takes no value, or it has one. Chips still waiting on a value show a dashed edge and aren't counted by `FilterActiveCount`. Use it to send only real filters to a server.

#### operatorLabel

An operator's display name: the translated one from `labels.operators` when given, else its own `label`. `describeFilter` takes the same map as an optional third argument.

#### resolveOperators

Returns the operators available for a field, applying `operators` and `disabledOperators`.
