The scroll area is a container with custom-styled scrollbars and optional edge fades. Use it for any overflowing region, like a sidebar, a chat log, or a long form, where the native scrollbar would look out of place.

## Examples

### Fade Edges

Use `fadeEdges` to add a CSS-mask fade at the edges that appears only where content is scrollable.

<ComponentPreview component="scroll-area" example="scroll-area-scroll-fade" />

The fade depth defaults to `min(12%, 2.5rem)`, 12% of the container capped at `2.5rem` so tall scrollers stay subtle. Tune it per instance by setting the `--scroll-fade-size` CSS variable on `viewportClassName`:

```tsx
<ScrollArea fadeEdges viewportClassName="[--scroll-fade-size:2rem]" />
```

With `nativeScroll`, the fade eases in and out over a fixed scroll distance (`6rem` by default, clamped to the scroll range so short scrollers still fully reveal). Adjust it with `--scroll-fade-reveal`:

```tsx
<ScrollArea fadeEdges nativeScroll viewportClassName="[--scroll-fade-reveal:4rem]" />
```

### Native Scroll Fade

Add `nativeScroll` to drive the fade with CSS scroll-driven animations instead of Base UI's measured overflow, falling back to a static fade where unsupported.

### Scroll Fade Without the Component

The same edge fade ships as a standalone CSS utility you can drop on any element with `overflow`, for scroll containers you didn't render with `ScrollArea` such as a code block, a table wrapper, or a third-party list. See [Scroll Fade](/docs/utils/scroll-fade).

### Fill Content Height

The content wrapper is only as tall as its children, so a short flex column has no slack for `mt-auto` to work with and a pinned footer floats up under the nav. Set `contentHeight="fill"` to stretch the wrapper to at least the viewport height and give that footer somewhere to sit.

<ComponentPreview component="scroll-area" example="scroll-area-fill-content" />

Children of a filled wrapper claim the height with `flex-1`:

```tsx
<ScrollArea contentHeight="fill" className="h-56">
  <div className="flex flex-1 flex-col">
    <nav>{/* items */}</nav>
    <div className="mt-auto">{/* pinned footer */}</div>
  </div>
</ScrollArea>
```

Use `flex-1` rather than `h-full`. A percentage height resolves against the wrapper's own height, which stays growable, so `h-full` collapses to nothing here.

The wrapper only ever grows from the viewport height, never locks to it, so long content still scrolls normally and keeps its natural size. Leave `contentHeight` at `"auto"` for lists, menus, and dialog bodies, where nothing needs to be pushed to the bottom.

### Content Width

`contentMinWidth` decides how wide the internal content wrapper may grow. It defaults to `"viewport"`, which keeps the wrapper at the visible width.

The alternative, `"fit-content"`, is Base UI's own default and lets the wrapper grow to its widest child. That sounds harmless but it switches on intrinsic sizing, and anything in the subtree that physically cannot shrink reports its full width upward. A `whitespace-pre` code block is the usual culprit. Nesting it in its own scroll area does not help, because a scroll container still passes its content's width up to whatever is measuring it.

The result is a panel meant to scroll vertically that quietly grows a horizontal scrollbar, with the nested scroller stretched wide enough that it never overflows and so never scrolls on its own:

```tsx
<SheetBody>
  <CodeBlock code={longUnwrappedLine} />
</SheetBody>
```

Under `"viewport"` the wrapper stays put and the code block scrolls inside its own box, which is what you want.

Sideways scrolling still works under `"viewport"`. Children that overflow keep extending the scroll range, so anything sizing itself with `w-max`, a fixed grid template, or a table's own width behaves exactly as it did before:

```tsx
<ScrollArea className="w-96">
  <div className="flex w-max gap-4">{/* scrolls sideways */}</div>
</ScrollArea>
```

What `"viewport"` gives up is the wrapper stretching across the whole scroll range. Padding on a child lands at the fold instead of the far end, so a horizontally scrolling child with its own padding loses that breathing room at the end of the scroll. Give the child an explicit width to get it back, or switch to `"fit-content"`:

```tsx
<ScrollArea contentMinWidth="fit-content">
  <div className="p-3">{/* padding survives at the scroll end */}</div>
</ScrollArea>
```

## API Reference

The ScrollArea component is built on top of [Base UI's ScrollArea](https://base-ui.com/react/components/scroll-area). All Base UI props are supported. The documentation below only covers custom props and modified defaults specific to our implementation.

For the complete Base UI API, see the [Base UI ScrollArea documentation](https://base-ui.com/react/components/scroll-area).

### Props

#### ScrollArea

Container with styled scrollbars and optional fade effects. Wraps Base UI's `ScrollArea.Root`.

<ApiPropsList>

<ApiProp name="fadeEdges" fullType="boolean | 'top' | 'bottom' | 'left' | 'right' | 'x' | 'y' | FadeEdge[]" defaultValue="false">
  Adds a subtle fade effect at the scroll edges using CSS masks. The fade
  appears when content is scrollable in that direction and disappears at
  boundaries. Works over any background color or pattern.

  - `true` - fade all edges
  - `"y"` - fade top and bottom
  - `"x"` - fade left and right
  - `"top"`, `"bottom"`, `"left"`, `"right"` - fade specific edge
  - `["top", "left"]` - fade multiple specific edges
</ApiProp>

<ApiProp name="scrollbarGutter" fullType="boolean" simpleType="boolean" defaultValue="false">
  Reserves space for the scrollbar when content overflows. This prevents layout
  shift when the scrollbar appears or disappears.
</ApiProp>

<ApiProp name="persistScrollbar" fullType="boolean" simpleType="boolean" defaultValue="false">
  Always show the scrollbar instead of fading it in on hover or scroll. Useful
  for interfaces where constant scroll position awareness is needed.
</ApiProp>

<ApiProp name="hideScrollbar" fullType="boolean" simpleType="boolean" defaultValue="false">
  Hides the scrollbar while keeping scroll functionality. Useful for carousels,
  touch-first UIs, or when using custom scroll indicators. Cannot be used with
  `persistScrollbar`.
</ApiProp>

<ApiProp name="nativeScroll" fullType="boolean" simpleType="boolean" defaultValue="false">
  Uses native browser scrolling instead of Base UI's ScrollArea. The scrollbar
  is styled to match using CSS, and fade edges use CSS scroll-driven animations
  (Chrome 115+, with static fallback for other browsers). Useful when you need
  native scroll behavior or want to avoid Base UI's overhead.

  Note: `persistScrollbar` is not supported with `nativeScroll`. With `nativeScroll`,
  `scrollbarGutter` always reserves space (CSS `scrollbar-gutter: stable`), while the
  default only reserves space when content overflows.
</ApiProp>

<ApiProp name="overscrollBehavior" fullType="'auto' | 'contain' | 'none'" defaultValue="contain">
  Controls the scroll chaining behavior when reaching the scroll boundary.

  - `"auto"` - default browser behavior, scroll chains to parent containers
  - `"contain"` - prevents scroll chaining to parent containers
  - `"none"` - prevents scroll chaining and disables bounce/rubber-band effects
</ApiProp>

<ApiProp name="contentMinWidth" fullType="'viewport' | 'fit-content'" defaultValue="viewport">
  How wide the internal content wrapper may grow.

  - `"viewport"` - hold the wrapper at the visible width, so content that cannot
    wrap does not give a vertical panel a horizontal scrollbar
  - `"fit-content"` - Base UI's default, growing the wrapper to its widest child

  Children that size themselves still scroll sideways under either value. Has no
  effect with `nativeScroll`, which renders no content wrapper.
</ApiProp>

<ApiProp name="contentHeight" fullType="'auto' | 'fill'" defaultValue="auto">
  How tall the internal content wrapper may grow.

  - `"auto"` - track the children, the usual case for lists and menus
  - `"fill"` - stretch to at least the viewport height, so a flex child can push
    a footer to the bottom with `mt-auto`

  Under `"fill"` the wrapper becomes a flex column, so children claim the height
  with `flex-1` rather than `h-full`. Long content still grows and scrolls
  normally. Has no effect with `nativeScroll`, which renders no content wrapper.
</ApiProp>

<ApiProp name="contentClassName" fullType="string" simpleType="string">
  Additional className for the internal content wrapper. Needed when a child
  relies on a percentage height against its parent (for example, Base UI's
  Select list gets `max-height: 100%` under `alignItemWithTrigger`), which only
  resolves if the wrapper has a definite height like `h-full`. Ignored with
  `nativeScroll`, which renders no content wrapper.
</ApiProp>

</ApiPropsList>
