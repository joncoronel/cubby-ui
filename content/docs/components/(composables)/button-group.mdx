A button group holds related actions on one shared surface, like a file's share, duplicate, and archive actions or an editor's undo and redo. A highlight glides from button to button as the pointer or keyboard focus moves along the row. To attach buttons to an input or select, use the `attached` variant. When one button stays selected, use [`ToggleGroup`](/docs/components/toggle-group) instead. When the row needs arrow-key navigation, use [`Toolbar`](/docs/components/toolbar).

## Composition

```text
ButtonGroup
├── Button
├── ButtonGroupSeparator
└── ButtonGroupText
```

Buttons inside a group take its style, so leave their `variant` unset. A button that has a `variant` keeps its own fill.

## Examples

### Variants

`outline` (the default), `soft`, `elevated`, and `solid` draw the shell; the buttons inside sit bare on it.

<ComponentPreview component="button-group" example="button-group-variants" />

| Value        | Use it for                                                                            |
| ------------ | ------------------------------------------------------------------------------------- |
| `"outline"`  | Actions on a page or card. The fill and border of an outline Button.                  |
| `"soft"`     | Editor and canvas chrome. The fill of a secondary Button, no edge.                    |
| `"elevated"` | Toolbars that float over content, like a selection menu. A raised surface and shadow. |
| `"solid"`    | A primary action and its options. The neutral fill.                                   |
| `"attached"` | Buttons attached to fields. See [Attached](#attached).                                |

### Separator

`ButtonGroupSeparator` splits actions into clusters. The line hides while the highlight is on a button next to it.

### Emphasis

Give one button a `variant` to mark it as the main action. It keeps its own fill while the rest of the group stays quiet.

### Pill

Each button sits 3px inside the shell, and the shell's corners are the buttons' radius plus those 3px, so both follow `--radius`. Set `[--radius:9999px]` on the group for a pill.

```tsx
<ButtonGroup className="[--radius:9999px]">…</ButtonGroup>
```

### With Text

`ButtonGroupText` holds a read-only label between buttons, like the count on a bar of bulk actions. It uses tabular numerals, so a changing count keeps its width. For a value people can type or step, use [`NumberField`](/docs/components/number-field).

<ComponentPreview component="button-group" example="button-group-text" />

### With Fields

Inputs and selects in a shell drop their own border and fill and sit in the row like the buttons. The highlight glides onto a select's trigger. An input lights in place while you hover or type, since it isn't an action. For fields that keep their own borders, use [Attached](#attached).

<ComponentPreview component="button-group" example="button-group-fields" />

### With Dropdown

Pair an action with a menu of related ones. The trigger keeps the highlight color while its menu is open. Menus measure their offset from the trigger, which sits 3px inside the shell, so add 3 to `sideOffset` to keep the usual gap from the shell's edge.

<ComponentPreview component="button-group" example="button-group-dropdown" />

### Orientation

Set `orientation="vertical"` to stack the buttons. Separators turn to match.

<ComponentPreview component="button-group" example="button-group-orientation" />

### Size

Set `size` on the group. Its outer height matches a Button of the same size, so a group lines up with buttons and inputs in the same row. The buttons inside are 6px shorter. Icon-only buttons still need an `icon` size to stay square.

<ComponentPreview component="button-group" example="button-group-size" />

### Nested

A group of groups acts as a layout wrapper with no shell of its own. Each inner group keeps its own shell and highlight, and takes the wrapper's `variant` and `size` unless it sets its own.

<ComponentPreview component="button-group" example="button-group-nested" />

### Attached

`variant="attached"` joins the buttons into one control and collapses the borders between them. The buttons keep their own variant here, so pass one, usually `outline`.

## Accessibility

The group renders `role="group"`. Give it an `aria-label` that names the set ("File actions", "Zoom"), and an `aria-label` on every icon-only button.

Tab moves through the buttons one at a time. For a long row where arrow keys should move between buttons, use [`Toolbar`](/docs/components/toolbar).

The highlight only marks where the pointer or focus is. Disabled buttons are skipped. Keyboard focus also gets the focus ring, so the highlight is never the only cue. With reduced motion, the highlight jumps to the next button instead of sliding.

The highlight uses CSS anchor positioning. In browsers without it, each button shows its own hover color instead.

## API Reference

### Props

#### ButtonGroup

Groups buttons on a shared surface. Renders a `div` with `role="group"` and accepts all `div` props.

<ApiPropsList>

<ApiProp
  name="variant"
  fullType='"outline" | "soft" | "elevated" | "solid" | "attached"'
  simpleType="string"
  defaultValue='"outline"'
>
  The shell. `attached` draws no shell and joins its children instead. A nested
  group defaults to its parent's variant.
</ApiProp>

<ApiProp
  name="size"
  fullType='"sm" | "default" | "lg"'
  simpleType="string"
  defaultValue='"default"'
>
  Outer height, matching Button's `sm`, `default`, and `lg` heights. The buttons
  inside fill it. Has no effect on `attached`, where the buttons size
  themselves.
</ApiProp>

<ApiProp
  name="orientation"
  fullType='"horizontal" | "vertical"'
  simpleType="string"
  defaultValue='"horizontal"'
>
  Lays the buttons out in a row or a column.
</ApiProp>

<ApiProp
  name="highlight"
  fullType="boolean"
  simpleType="boolean"
  defaultValue="true"
>
  Glides one shared highlight between buttons, using CSS anchor positioning.
  With `false`, or in a browser without anchor positioning, each button paints
  its own hover. Has no effect on `attached`.
</ApiProp>

</ApiPropsList>

#### ButtonGroupSeparator

A line between buttons. Wraps [`Separator`](/docs/components/separator) and accepts its props.

<ApiPropsList>

<ApiProp
  name="orientation"
  fullType='"horizontal" | "vertical"'
  simpleType="string"
  defaultValue="perpendicular to the group"
>
  Direction of the line. Defaults to vertical in a row and horizontal in a
  column.
</ApiProp>

</ApiPropsList>

#### ButtonGroupText

A non-interactive segment for a label or value. Renders a `div` and accepts a `render` prop, for example `render={<label />}` to label an input in an attached group.

## Upgrading

If you're reinstalling over an earlier version, check these changes:

| Before                                       | Now                                                                                                 |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| Children fused into one bordered control     | Default is `outline`, a shell with bare buttons inside. Pass `variant="attached"` for the old look. |
| `ButtonGroupSeparator` defaulted to vertical | Perpendicular to the group, so vertical groups no longer need `orientation="horizontal"`.           |
| Buttons in a group set `variant="outline"`   | Leave `variant` unset in a shell variant. A set variant now marks the button as the main action.    |
