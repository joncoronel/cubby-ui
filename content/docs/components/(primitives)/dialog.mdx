A dialog is a modal window that overlays the page and waits for the user to act. Use it for focused tasks like confirming a destructive action, editing a record, or completing a short form without leaving the current view.

## Composition

```text
Dialog
├── DialogTrigger
└── DialogContent
    ├── DialogHeader
    │   ├── DialogTitle
    │   └── DialogDescription
    ├── DialogBody
    └── DialogFooter
        └── DialogClose
```

`DialogContent` composes the portal, viewport, backdrop, and popup internally, so you wrap your content directly inside it.

### Outside Scroll

Set `scroll="outside"` on `DialogContent` to let the popup grow past the viewport and scroll the area around it instead.

| Value       | Behavior                                                                              |
| ----------- | ------------------------------------------------------------------------------------- |
| `"inside"`  | Popup is capped to the viewport. `DialogBody` scrolls, header and footer stay pinned. |
| `"outside"` | Popup grows past the viewport. The area around it scrolls, so the whole card moves.   |

## Accessibility

Base UI handles the dialog role, labelling, focus trapping, and Escape. One thing is layered on top:

`scroll="outside"` moves initial focus to the popup itself rather than the first focusable child. Without it the browser scrolls whatever it focuses into view, so a tall dialog can open part-way down its own content. The popup's focus ring is suppressed in this mode because focus lands there on open rather than by user action. Pass `initialFocus` to choose a different target.

The close button sits at the top of the card, so under `scroll="outside"` it scrolls out of view on a tall dialog. Escape still closes it. Give a long dialog a footer close action, or set `showCloseButton={false}` and place your own.

## API Reference

The Dialog component is built on top of [Base UI's Dialog](https://base-ui.com/react/components/dialog). All Base UI props are supported. The documentation below only covers custom props and modified defaults specific to our implementation.

For the complete Base UI API, see the [Base UI Dialog documentation](https://base-ui.com/react/components/dialog).

### Utilities

#### createDialogHandle

Creates a handle that connects a dialog to one or more external `DialogTrigger` components. Useful when the triggers need to live outside the `Dialog`, for example when each row in a list has its own trigger but they all share one dialog.

```tsx
import { createDialogHandle } from "@/registry/default/dialog/dialog";

const handle = createDialogHandle();
```

##### Passing data from the trigger to the dialog

The handle accepts an optional `<Payload>` generic that types a value each trigger can pass along. The dialog reads it through a render-prop child, so you can render different content per trigger without duplicating the dialog markup.

```tsx
type User = { id: string; name: string };

const handle = createDialogHandle<User>();

// Multiple triggers, each with its own payload:
users.map((user) => (
  <DialogTrigger key={user.id} handle={handle} payload={user}>
    Edit {user.name}
  </DialogTrigger>
));

// One shared dialog that renders based on the active trigger:
<Dialog handle={handle}>
  <DialogContent>
    {({ payload: user }) => (
      <DialogHeader>
        <DialogTitle>{user?.name}</DialogTitle>
      </DialogHeader>
    )}
  </DialogContent>
</Dialog>;
```

Without the `<User>` generic, `payload` inside the render prop resolves to `unknown`.

### Props

#### Dialog

Root component. Forwards all props to Base UI's `Dialog.Root`, with modified defaults for the `modal` prop.

<ApiPropsList>

<ApiProp
  name="modal"
  fullType='boolean | "trap-focus"'
  simpleType="boolean"
  defaultValue="true"
>
  Behavior is unchanged from Base UI, but when set to `false` or `"trap-focus"`,
  `DialogContent` skips the backdrop and wires `pointer-events` so the page
  remains interactive. Also changes the default of `disablePointerDismissal` to
  `true` so clicks on the page don't close the dialog. Pass
  `disablePointerDismissal={false}` explicitly to opt back into outside-click
  dismissal.
</ApiProp>

</ApiPropsList>

#### DialogContent

Dialog container with centered positioning. Composes `Dialog.Portal`, `Dialog.Viewport`, and `Dialog.Popup`. Also renders `Dialog.Backdrop` when the dialog is modal. Props are forwarded to `Dialog.Popup`.

<ApiPropsList>

<ApiProp name="showCloseButton" fullType="boolean" defaultValue="true">
  Show or hide the X close button in the dialog header. Custom prop not
  available in Base UI.
</ApiProp>

<ApiProp name="variant" fullType='"default" | "inset"' defaultValue='"default"'>
  Visual variant of the dialog. The `inset` variant applies a muted background
  to the footer that extends to the dialog edges.
</ApiProp>

<ApiProp name="scroll" fullType='"inside" | "outside"' defaultValue='"inside"'>
  Where overflow scrolls. `inside` caps the popup to the viewport and scrolls
  `DialogBody`, keeping the header and footer pinned. `outside` lets the popup
  grow past the viewport and scrolls the area around it, so the whole card
  moves; `DialogBody` renders without its inner scroller and its ScrollArea
  props have no effect. Treat as fixed for the dialog's lifetime: changing it
  while open remounts the popup. Custom prop not available in Base UI.
</ApiProp>

<ApiProp
  name="initialFocus"
  fullType="boolean | RefObject | ((openType) => boolean | HTMLElement | null | void)"
  defaultValue='Base UI default, or the popup under scroll="outside"'
>
  Base UI prop, with a modified default. Under `scroll="outside"` it defaults to
  the popup element instead of the first focusable child, so opening a tall
  dialog does not scroll straight past the header. Pass your own value to
  override.
</ApiProp>

<ApiProp name="level" fullType="1 | 2 | 3 | 4 | 5 | 6 | 7 | 8" defaultValue="5">
  Surface elevation level. See the [Surfaces](/docs/getting-started/surfaces)
  docs. Dialogs default to `5`, comfortably above popovers and dropdowns at
  level 3.
</ApiProp>

<ApiProp
  name="shadowLevel"
  fullType="1 | 2 | 3 | 4 | 5 | 6 | 7 | 8"
  defaultValue="5"
>
  Shadow weight. Defaults to `5` for the typical dialog-sized element (~400 to
  800px).
</ApiProp>

</ApiPropsList>

#### DialogBody

Scrollable content area within the dialog.

<ApiPropsList>

<ApiProp
  name="nativeScroll"
  fullType="boolean"
  defaultValue="false"
>
  Use native browser scrolling instead of Base UI's ScrollArea. Fade edges still
  work using CSS scroll-driven animations (Chrome 115+, with static fallback).
  Note: `persistScrollbar` is not supported with `nativeScroll`.

Has no effect when `DialogContent` uses `scroll="outside"`.

</ApiProp>

<ApiProp
  name="fadeEdges"
  fullType="boolean | 'top' | 'bottom' | 'left' | 'right' | 'x' | 'y' | FadeEdge[]"
  defaultValue="true"
>
  Controls the fade effect on scroll edges. See [ScrollArea](/docs/components/scroll-area#custom-props) for all options.

Has no effect when `DialogContent` uses `scroll="outside"`.

</ApiProp>

<ApiProp
  name="scrollbarGutter"
  fullType="boolean"
  defaultValue="false"
>
  Reserves space for the scrollbar when content overflows, preventing layout shift.

Has no effect when `DialogContent` uses `scroll="outside"`.

</ApiProp>

<ApiProp
  name="persistScrollbar"
  fullType="boolean"
  defaultValue="false"
>
  Always show the scrollbar instead of fading it in on hover or scroll.

Has no effect when `DialogContent` uses `scroll="outside"`.

</ApiProp>

<ApiProp
  name="hideScrollbar"
  fullType="boolean"
  defaultValue="false"
>
  Hides the scrollbar while keeping scroll functionality.

Has no effect when `DialogContent` uses `scroll="outside"`.

</ApiProp>

</ApiPropsList>
