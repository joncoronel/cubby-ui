A switch toggles a single setting on or off and applies the change immediately. Use it for instant preferences like notifications or dark mode, not for choices a user submits later with a form (reach for [`Checkbox`](/docs/components/checkbox) there).

### Color

Use `color` to set the checked track. The unchecked track is a translucent overlay and does not change.

<ComponentPreview component="switch" example="switch-color" />

| Color     | Description                                                         |
| --------- | ------------------------------------------------------------------- |
| `primary` | The default, your brand colour.                                     |
| `neutral` | A dark neutral, for switches that should not compete for attention. |

For anything outside the scale, set `--switch-fill` on the switch or any ancestor. The hover step is derived from whatever it resolves to, so a custom colour gets a matching hover without a second value:

```tsx
<Switch className="[--switch-fill:var(--color-emerald-600)]" />
```

Each preset pairs its fill with a matching thumb while checked, so `neutral` gets a dark thumb in dark mode where white would vanish. Unchecked, the thumb is white on every preset. A custom fill keeps the white thumb, which disappears against a light colour, so set `--switch-thumb` alongside it. Qualify it with `data-checked:` when the thumb you want is dark: unqualified it applies to both states, and the unchecked track is a translucent overlay that a dark thumb vanishes into. Like `--switch-fill`, it works from an ancestor too:

```tsx
<Switch className="[--switch-fill:var(--color-amber-300)] data-checked:[--switch-thumb:var(--color-amber-950)]" />
```

### Shapes

Use `shape` to set the thumb's silhouette, which the track follows.

<ComponentPreview component="switch" example="switch-shapes" />

| Shape      | Description                                      |
| ---------- | ------------------------------------------------ |
| `circle`   | The default, a round thumb.                      |
| `pill`     | A wider, rectangular thumb.                      |
| `squircle` | A squared-off thumb, for a more mechanical look. |

`squircle` uses CSS `corner-shape`. Browsers without it fall back to a rounded square.

### Sizes

Use `size` to set the thumb height, which drives the track dimensions.

<ComponentPreview component="switch" example="switch-sizes" />

| Size      | Thumb | Track height | Where it fits                     |
| --------- | ----- | ------------ | --------------------------------- |
| `xs`      | 14px  | 18px         | Dense rows: menu items, toolbars. |
| `sm`      | 16px  | 20px         | Compact settings rows and cards.  |
| `default` | 20px  | 24px         | Standalone form control.          |

[Dropdown Menu](/docs/components/dropdown-menu), [Context Menu](/docs/components/context-menu) and [Menubar](/docs/components/menubar) use `xs` for their `indicator="switch"` items, so a switch inside one already matches the surrounding text.

For a size the scale does not cover, set `--thumb-size`. It also takes responsive variants, which the preset cannot:

```tsx
<Switch className="sm:[--thumb-size:--spacing(3.5)]" size="sm" />
```

### Motion

Use `motion` to set what the thumb does while the switch toggles.

<ComponentPreview component="switch" example="switch-motion" />

| Motion    | Description                                                                |
| --------- | -------------------------------------------------------------------------- |
| `default` | The thumb slides across at a constant width.                               |
| `stretch` | The leading edge crosses first, so the thumb spans the track and flattens. |

Hover and press behave the same either way. The thumb widens on hover, widens further and flattens on press, and always reaches into the empty half of the track. Both respond to a `group/switch` ancestor as well as to the switch itself, so `Label className="group/switch"` makes a whole row drive the thumb; menu items already do this. The group is named on purpose: a bare `group` would let any ancestor a consumer marks for an unrelated hover effect drive every switch inside it.

To retune, set `--switch-press-squash` (use `0` to drop the flattening), `--switch-hover-ext`, `--switch-press-ext`, or `--switch-duration`:

```tsx
<Switch className="[--switch-press-squash:0px]" motion="stretch" />
```

## API Reference

The Switch component is built on top of [Base UI's Switch](https://base-ui.com/react/components/switch). All Base UI props are supported. The documentation below only covers custom props specific to our implementation.

For the complete Base UI API, see the [Base UI Switch documentation](https://base-ui.com/react/components/switch).

### Props

#### Switch

Toggle control for binary on/off states. Wraps Base UI's `Switch.Root` and `Switch.Thumb`.

<ApiPropsList>

<ApiProp
  name="color"
  fullType='"primary" | "neutral"'
  simpleType="string"
  defaultValue='"primary"'
>
  Checked track colour. `className` or an ancestor can set `--switch-fill` to
  override it for a colour outside the scale; the hover step is derived from
  whatever the fill resolves to either way.
</ApiProp>

<ApiProp
  name="shape"
  fullType='"circle" | "pill" | "squircle"'
  simpleType="string"
  defaultValue='"circle"'
>
  Sets the thumb's aspect ratio, corner radius and travel distance together. The
  track picks up the same corner treatment, so the two stay in step.
</ApiProp>

<ApiProp
  name="size"
  fullType='"xs" | "sm" | "default"'
  simpleType="string"
  defaultValue='"default"'
>
  Thumb height, which drives the track dimensions. Sets `--thumb-size`, so
  `className` can still override it for a one-off or responsive size.
</ApiProp>

<ApiProp
  name="motion"
  fullType='"default" | "stretch"'
  simpleType="string"
  defaultValue='"default"'
>
  What the thumb does while the switch toggles. `"stretch"` sends the leading
  edge first, so the thumb spans the track mid-toggle and flattens as it goes.
  Hover and press are unaffected.
</ApiProp>

</ApiPropsList>

Switch has no `variant` prop: colour is its own `color` prop, which keeps `variant` free for a future treatment axis. The unchecked track uses `--switch-track`, a translucent overlay that adapts to whatever substrate it sits on, so one colour works on a page, a Card, or a toolbar. The thumb is white unchecked, and follows the `color` preset's foreground while checked. Set `--switch-track` and `--switch-track-hover` to retune the track and its hover step. See the [Surfaces](/docs/getting-started/surfaces) docs.

The 2px inset around the thumb is a fixed offset rather than space the layout divides, and the track width, thumb width and travel distance are snapped to whole pixels with CSS `round()`, so a `p-*` class will not change it. The checked track's hover step uses relative color syntax (`oklch(from ...)`), available in all current browsers; in older ones without support the hovered track renders transparent, so apply your own hover with a `supports-*` variant if you target those. The motion runs off registered custom properties, so it needs `@property`. Those registrations ship in `switch.css`, which the component imports itself: nothing to wire up, but drop that import and the switch changes state without animating, the same as under `prefers-reduced-motion`.
