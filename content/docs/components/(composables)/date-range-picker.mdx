The date range picker is a field that opens a calendar popover for choosing a start and end date. Use it for report ranges, booking windows, and date filters.

To select a single date, use [`DatePicker`](/docs/components/date-picker) instead.

## Examples

The value changes only after you pick both ends; closing the popover halfway keeps the previous range.

### Typing a Range

Use `editable` to make the field a text input. It reads two dates joined by a dash, "to", or "until" ("mar 3 – 12", "today to fri", "Dec 28 – Jan 4"), relative spans like "last 30 days" or "next 2 weeks", and a single date as a one-day range. A second date missing its month or year takes them from the first, so the field also parses its own output, "Oct 1 – 8, 2026". Before you commit, the hint shows the range and its length, or why it breaks `minNights`, `maxNights`, or a blocked date.

### Minimum and Maximum Length

Use `minNights` and `maxNights` to limit the range's length, counted in nights between the ends, and `minDate` and `maxDate` to limit where it falls. For stays, set `labels.duration` to count nights instead of days in the status line and its announcement.

## Accessibility

The trigger is a button that opens the calendar in a popover and moves focus into it. Use the arrow keys to move between days and `Enter` or `Space` to set the start and then the end; the preview band follows keyboard focus as well as the pointer. A polite live region announces each step to screen readers ("pick an end date", then the finished range and its length), whether or not `showStatus` displays it. `Escape` closes the popover without a change.

## API Reference

DateRangePicker composes [`Calendar`](/docs/components/calendar) in `range` mode inside a [`Popover`](/docs/components/popover), with a trigger styled like an [`Input`](/docs/components/input). Props not listed below (`id`, `aria-*`, event handlers) go to the trigger button.
